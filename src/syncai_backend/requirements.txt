# scipy: helpers/pcd_to_gridmap.py morphology passes (ndimage) — imported at
# startup via the map router. Range-pinned, and the ceiling is about numpy, not
# scipy: newer scipy raises its numpy floor, and on a fresh image pip would
# "helpfully" upgrade numpy past what the ROS ecosystem tolerates (same class
# of problem as the kokoro-onnx pins below). 1.8–1.10 all accept numpy
# 1.19–1.26, i.e. whatever the container already has stays. The conversion was
# verified bit-identical to the retired tools/pcd_to_gridmap.py on 1.8.0 (the
# apt python3-scipy this line replaced); ndimage's API is stable across the
# range.
scipy>=1.8,<1.11
# open3d: helpers/traversable.py (intensity/normal traversability segmentation
# and ground repair). NOT imported at backend startup — the map router imports
# helpers/pcd_to_gridmap, which is deliberately open3d-free, and traversable.py
# is imported inside the function that runs the pipeline. It is here because the
# pipeline was developed against open3d 0.19 in a standalone tool and porting its
# KD-tree normal estimation, DBSCAN, covariance estimation and radius filters to
# cKDTree + ndimage was the rejected alternative (it would have kept the image
# free of a ~100 MB aarch64 wheel, at the cost of the segmentation no longer
# being bit-comparable to the offline tool the parameters were tuned in).
#
# **Watch the numpy ceiling when bumping this.** The whole point of the scipy pin
# above is that pip must not drag numpy past the 1.26 the ROS ecosystem
# tolerates, and open3d's metadata is the other dependency in this file with an
# opinion about numpy. If `pip install -r requirements.txt` in the container
# starts resolving numpy 2.x, install open3d the way the Dockerfile installs
# kokoro-onnx — `--no-deps`, after this file's install — rather than loosening
# the numpy constraint. The helper only touches open3d's core geometry/io, which
# needs numpy and nothing else in its dependency list.
open3d>=0.18,<0.20
# --- TTS (gateways/tts) -------------------------------------------------------
# kokoro-onnx itself is NOT here: its metadata demands onnxruntime>=1.20.1 and
# numpy>=2, and both are wrong for this machine — ORT >= 1.19's CPU-topology
# probe corrupts the heap on the Orin whenever nvpmodel keeps cores offline
# (MODE_30W offlines 8-11; 1.18.1 predates that code and works), and numpy 2
# would be forced over the ROS ecosystem's 1.26. The API kokoro-onnx actually
# calls is fine against both pins, so the Dockerfile installs it with
# --no-deps and its real dependencies are spelled out here instead:
onnxruntime==1.18.1  # kokoro-onnx runtime — PINNED, see above before bumping
colorlog  # kokoro-onnx dep
espeakng-loader  # kokoro-onnx dep (bundled espeak-ng for English G2P)
phonemizer-fork  # kokoro-onnx dep
opencv-python-headless  # encode map image to PNG (+ future overlay drawing)
httpx  # test-only: required by fastapi.testclient.TestClient (see test/)
